# 設計：04 空間的枯（跟著熱度的結尾）

> 寫於 2026-11-11。狀態：草稿，待使用者看過。
> 讀者：接手實作的人。讀完應該不用再問使用者就能排計畫。
> 前情：草稿 tag `exp04-o`（押花樹加一條手動「枯」滑桿，葉落、枝斷、落地）。使用者看過說「不錯」。

## 1. 意圖

使用者的話：「目前互動是有的，但總感覺少了故事感」→ 追問之後是「**沒有開頭跟結尾**」。現在每一筆長成一株就永遠停在那裡，整個作品像一個一直開著的生態缸，隨時來、隨時走，沒有一段從開始到結束的經歷。

這一輪給作品一個結尾，而且結尾和開頭是同一件事的兩端：**畫面上的一切都靠你的手維持**。你畫，植物活；你停手，熱度退，園子開始枯，葉子一片片落下、細枝斷掉倒在地上，退到底就是結尾，不用按任何鍵。再畫一筆，新的一株在殘骸之間長出來。

使用者在三種結尾裡選的是這一種（另外兩種是「每株有壽命」、「一季一次定時倒數」），枯的樣子選的是「**真的凋零：葉子落下、枝條斷掉、掉到地上**」，不是乾燥花式的定格褪色。

## 2. 目標、非目標、反目標

**目標**
- 停手之後，畫面自己走到一個結尾；整個過程不需要任何操作。
- 枯是慢的、零零落落的，看得出「正在發生」，不是一下全掉。
- 掉下來的東西留在地上，越積越多，成為這幅畫的「土」；枯掉的不會復活。
- 新的一筆落下，熱度回來，還沒掉的停在那裡不再繼續枯；新的一株從 0 開始。
- 聲音跟著：弦樂墊先退、葉落有很輕的顆粒、枝斷有一下反轉或 glitch，而且這些**不推熱度**。
- 時間尺度留成可調參數，使用者會自己試。

**非目標（這一輪不做）**
- 其他四種植物（草、曼珠沙華、紫羅蘭、丁香）各自的枯法：列在 §8 當第二階段，先不做。它們在這一輪**不枯**，照舊永遠停在那裡。
- 落葉、斷枝的物理互動（彼此碰撞、堆疊成堆）：各自落地躺平就好。
- 風把落葉吹走、殘骸慢慢分解消失。
- 02 筆、03 景深那兩頁。
- 開頭的儀式（例如空白時的提示、標題）：這一輪只靠「第一筆落下才一切啟動」這個既有的事實當開頭。

**反目標（做到也算失敗）**
- 一喘口氣就枯：停手十幾秒葉子就掉，使用者會覺得被催。
- 像按了重置鍵：整株一瞬間消失或變色。
- 枯了一半再畫，舊的突然復活、或落葉飛回枝上。
- 枯的聲音把鼓和鋼琴叫回來（枯事件推了熱度）。
- 畫面很多株之後落葉太多讓幀率掉到看得出卡。

## 3. 限制

- 工具鏈不變：Vite + pnpm + TypeScript strict + Vitest + Biome；04 是 three.js。
- 每一輪結束照 `docs/process-log.md` 的慣例切 tag、加一列（使用者要能回到任何一輪）。
- 熱度目前只存在聲音引擎裡（`src/sound/theory/heat.ts` 的 `Heat`，`BotanicaEngine` 私有）；關聲音或切回舊引擎時 04 的主迴圈根本不呼叫引擎。**枯不能依賴聲音開著**。
- 草稿的資料結構沿用：`Segment3D` 與 `Leaf3D` 已帶 `tip`（哪支芽長的），`PlantView` 已有 `wither` 欄位、葉與枝的狀態機、`groundY`。

## 5. 枯的時鐘

### 5.1 熱度要離開聲音引擎一份

04 的主程式自己持有一個 `Heat`（和引擎用同一個 class、同一組 `HEAT_BUMP`），在放開一筆（plant）、分枝（branch）、長葉（leaf）時各加一次。引擎裡那份不動（它還要管鼓和鋼琴）。兩份數值一樣，但畫面那份不受「聲音開沒開」影響。

### 5.2 乾燥時鐘 D（全域、只進不退）

- 一個全域的數字 D（秒），一開始 0。
- 每幀：如果「距離上一次活動 ≥ 寬限」**而且**「熱度 < 門檻」，D 以 1 秒/秒前進；否則停住。永遠不倒退。
- 「活動」= 放開一筆、分枝、長葉（和熱度加能量的時機一樣）。**畫線中（還沒放開）也算活動**，不然畫很長一筆的途中園子會開始枯。
- 預設：寬限 25 秒、門檻 0.3。熱度半衰期 20 秒：單獨一筆（熱度約 0.18）本來就低於門檻，停手 25 秒就開始；畫得很密（能量到上限 5、熱度約 0.99）要等約 76 秒熱度才降到 0.3，所以畫得越多活得越久，這就是「跟著熱度」的意思。

### 5.3 每株的枯 = 它出生之後 D 走了多少

- 每株記下出生時的 D（`bornD`）。
- `wither = clamp((D − bornD) / 全枯秒數, 0, 1)`，預設全枯秒數 100。
- 於是：新株從 0 開始；熱度回來 D 停住，所有株的 wither 停住；D 永不倒退，所以掉了的不會回去。
- **每株的 wither 只增不減**（記住歷來最大值）：使用者把「全枯秒數」拉大、或手動滑桿拉上去再放下，算出來的值會變小，不鎖住的話落葉會飛回枝上。`PlantView` 草稿裡「拉回去會復原」的分支因此在正式版走不到，留著無妨。
- `wither` 每幀推給 `PlantView.wither`，和草稿一樣。

### 5.4 可調參數（放在「此種」的進階，押花樹才顯示）

| 參數 | 預設 | 範圍 |
|---|---|---|
| 寬限（秒） | 25 | 5–90 |
| 熱度門檻 | 0.3 | 0–1 |
| 全枯（秒） | 100 | 20–300 |
| 手動枯（草稿滑桿） | 0 | 0–1 |

手動滑桿保留當除錯：只要它 > 0，就用 `max(自動, 手動)`。

純函式放 `src/growth/wither.ts`（D 的推進、每株 wither 的算法），附測試：寬限內不走、熱度高不走、活動後停住、新株從 0、永不倒退。

## 6. 畫面（押花樹）

草稿已經做了，正式版沿用，調的地方列出來：

- 葉：各自的脫離點落在 wither 0.08–0.63；靠近脫離點前 0.3 的區間顏色往褐黃走（六階材質快取）；脫離後慢慢飄、左右擺、翻轉，落地躺平、葉面朝上。
- 枝：同一支芽的段是一條枝；斷點在 wither 0.5–0.98，越深（越細、越末梢）越早；整條繞斷點翻滾落地；使用者畫的主幹不斷。
- 枝色隨 wither 往灰褐退 75%。**使用者畫的主幹也一起變色**（草稿只重上色植物長的段，主幹沒變；正式版把畫的段也記進去）。
- 全部枯完（wither = 1）之後，這株就是「殘骸」：留在原地，不消失。

要改的：
- 草稿裡落葉速度（`LEAF_FALL` 0.32 單位/秒）和斷枝翻滾（角速度 0.8–2.2 rad/s、重力 2.2）是猜的；正式版把這兩個開成進階參數讓使用者調。
- 性能：落葉是一片一片的 Mesh（各自投影，一片兩次 draw call），十株活著的時候可能就已經是幾千個 draw call。驗收標準是**相對的**：先量「十株押花樹活著」的基線，再量「十株全枯」，枯完不能比基線低超過 10 fps。把葉子全面改成 InstancedMesh 是另一輪的事，不包進這一輪；如果基線本身就很差，記下數字、另案處理。

## 7. 聲音

- `SoundEngine` 加可選的 `onWither?(e: { kind: 'leaf' | 'branch'; x: number; y: number; depth: number }, voice?: string)`。舊引擎不實作。
- `BotanicaEngine.onWither`：**不呼叫 `idle.activity`、不加熱度**。
  - leaf：一半機率略過；過了每秒上限就略過；用那株的顆粒素材，音量比正常長葉再低 8 dB（也就是比分枝低 16 dB），反轉機率拉高到 0.6。
  - branch：抽 `swell` 或 `glitchfx`（各半），反轉播放，經過偶發層（drips）那條路，音量和現在的 drip 一樣（−6 dB，不另外壓）；swell 和 glitch 一樣做調的位移。偶發層目前沒有反轉與音量參數，加成 `glitch(id, shift, { reverse?, gainDb? })` 這類可選參數，`index.ts`、假層、測試跟著改。
  - leaf 的時機是**落地那一刻**，不是脫離枝條那一刻：掉下來的「落」在地上才發生，而且一批葉子同時脫離時聲音會擠在一起，落地時間自然散開。事件的 `x, y` 用落地點。
- 弦樂墊、鼓、鋼琴不用動：它們本來就隨 release 和熱度退掉，而且熱度退得比畫面快，自然就是「聲音先安靜、葉子才黃」。
- 底（風、水）不動：結尾仍有風聲，像空掉的園子。
- 枯到底之後，偶發層照舊每 15–40 秒一滴水或一聲 glitch，就是結尾的聲音。

## 8. 第二階段：其他植物的枯（這一輪不做，先記）

| 植物 | 枯法草案 |
|---|---|
| 草 | 變黃、一根根倒伏，不掉 |
| 曼珠沙華 | 花絲先垂、花瓣一片片落，莖最後倒 |
| 紫羅蘭 | 花穗從上往下掉花、葉子落 |
| 丁香 | 小花一粒粒落成一地紫、葉子落、木質枝留著 |

每一種都是：各自的 View 加 `wither` 欄位、自己的狀態機；時鐘和聲音接點共用這一輪做好的。

## 9. 留給實作者的

- `Heat` 放哪：留在 `src/sound/theory/heat.ts` 讓 04 直接 import，或搬到 `src/growth`，實作者決定；不要複製一份邏輯。
- 「活動」怎麼從主迴圈通知時鐘：目前 `sound()` 那個閉包在送事件給引擎，時鐘的 `activity()` 可以放在同一個地方，但要放在 `state.sound.enabled` 判斷之**外**。
- 葉落事件要帶 `x, y`（0..1 畫面座標）給聲像用，主迴圈已有從世界座標換算的寫法，沿用。
- 測試：`src/growth/wither.ts` 純函式；`BotanicaEngine.onWither` 加「不改熱度、不改 idle」的測試（`engine.test.ts` 已有假的 deps 可用）。
