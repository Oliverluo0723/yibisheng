# 從 Ooame 和 InkField 借的設計哲學

> 整理日期：2026-11-11（exp04-p 之後）
> 來源：
> - 大雨-Ooame／Haiku（Giorgio Sancristoforo）：https://www.giorgiosancristoforo.net/ooame/ 的文字與介面截圖
> - InkField（ileivoivm）：tech/ 的「作品概述」、tech/emotion-intention.html（情緒與意圖）；技術細節另見 [inkfield-tech-notes.md](inkfield-tech-notes.md)
> - 使用者當天的回饋：「押花樹多了有點吵，而且單調，希望每株聲音可以特別」「植物跟植物間應當有聲音關聯，且每個聲音要不同」
>
> 兩件作品都只能學概念。Ooame 是付費軟體、沒有原始碼；InkField 原始碼授權未開放。

## 0. 一句話

Ooame 教我們「一個物件一首俳句，物件之間有連線，全部鎖在同一個慢脈搏上」；
InkField 教我們「筆跡本身就帶著人的狀態，作品是紀錄也是系統」。
我們的作品剛好站在中間：**每一筆是一個人的手勢，長成一株有自己聲音的植物，植物之間用同一個脈搏和同一組和弦互相關聯。**

## 1. Ooame 的原則

| 原則 | 它怎麼做 | 我們現在 | 可以用 |
|---|---|---|---|
| **一個物件一首俳句** | 畫面上十幾個小物件，每個有自己的節奏細分（2n／4n／8n／16n／32n）、一小段素材、一張稀疏的點陣 pattern、一個效果（REV／GRA／BIT／LPF／HPF／BPF／DEL） | 所有押花樹從同一個袋子抽，顆粒永遠是鋼琴、鋼琴、鐘，差別只在切片、聲像這種細節 | **一株樹＝一個節奏物件**：放開時定下細分、素材、效果、音域、pattern，之後長的每一枝都照它出聲 |
| **物件之間有連線** | SYNC LOOP（兩個物件鎖在一起循環）、JUMP（一個播完跳到另一個） | 各株各響，沒有關係 | 見第 3 節「植物之間的關聯」 |
| **全部鎖在一個慢脈搏** | 63 bpm、16n，所有物件對拍 | 引擎有 bpm 和小節線，但只有鼓和鋼琴用；顆粒是事件來了就響 | 樹的 pattern 走引擎的拍子，幾株一起響是對拍的、互相讓位的 |
| **紋理變厚、變薄** | 作者說這是唯一的動態：「the way a texture thickens or thins」 | exp04-p 的熱度曲線就是這個：畫越多越密、停手退潮 | 聲音也吃同一條曲線：熱時讓更多株一起響，冷時只剩一兩株；同時響的株數有上限 |
| **只定規則、比例、機率** | 引 Umberto Eco「開放作品」：作者設邊界，當下決定發生什麼，每次不同 | 配方從種子抽，已經是這個做法 | 保留；但「不同」要差得夠開才聽得出來（細分、音域、效果三個軸至少差兩個） |
| **沒有結尾** | 試玩版十分鐘重開；正式版一直播 | 我們有枯 | 我們不照抄：枯就是我們的結尾（見第 4 節） |
| **每個物件有名字** | 每個物件旁邊一首俳句（蝉の声／川は静かに流れて／無心なり） | 無 | 之後可以考慮：每株樹有一行字，從手勢和種子生出來（先不做） |

## 2. InkField 的原則

| 原則 | 作者的話 | 我們現在 | 可以用 |
|---|---|---|---|
| **繪畫是事件不是圖像** | 「Drawing is not an image. It is an event.」「作品既是紀錄，也是系統」 | 筆觸存成資料，畫面和生長從資料生出來；聲音也是 | 一株樹的聲音也要能從「筆觸資料 + 種子」完整重算，不靠當下的狀態。之後做重播才接得起來 |
| **筆跡讀得出人的狀態** | 「速度是急切，停頓是猶豫，壓力是決心」；速度是「情緒的量化投射」 | SpringPen 已經在算速度，手勢追蹤有位置時間；但這些資料只用來決定線條粗細 | **手勢決定這株的個性**：慢而有停頓的一筆 → 稀、低、長尾音；快而果決的一筆 → 密、高、短音。這回答了「每株要不同」，而且不同是觀眾自己畫出來的，不是抽籤 |
| **停頓的分布比次數重要** | 「均勻散佈的暫停像呼吸，集中在中段的暫停像掙扎」 | 無 | 一筆裡的停頓位置變成 pattern 的空拍：均勻的停頓 → 規律的節奏；中段糾結 → 不規則、有 glitch |
| **呼吸空間、留白** | 「小的東西需要更多留白才不會窒息」 | 一放開就綻放，顆粒事件來了就響，沒有讓位 | **小樹要更多安靜**：冷的時候一株小樹周圍留長的空拍；株數多時每株更稀，不是更密。這直接治「吵」 |
| **不靠運氣，靠種子；一次一步** | 「不錄結果，錄過程。不靠運氣，靠種子。」 | 生長用固定步長、種子可重現；聲音的顆粒靠即時事件 | 聲音也改成「pattern 由生長事件逐步寫入」而不是「事件直接出聲」，就和生長一樣可重現 |
| **餘韻** | 放開後墨還會擴散一下再歸零 | 綻放有 release | 樹枯掉時聲音不要瞬間消失：pattern 的格子跟著枝斷一格一格熄，最後留一個長的尾音 |
| **共繪是「AI 回應我這一筆」** | 不是幫你填滿畫布 | 系統回應每一筆（長、響） | 植物之間的「回應」也要是這種：一株新樹是對前一株的回應，不是另起爐灶（見第 3 節） |

## 3. 植物之間的聲音關聯（使用者的要求）

每株要不同，但彼此有關。兩件作品給了三種「關」法，可以同時用：

1. **同一個脈搏（Ooame SYNC）**
   所有樹走引擎的 bpm。每株自己的細分不同（4n、8n、16n、三連音），所以是不同的聲音，但一起響是對拍的。
2. **同一組和弦，不同的音（我們本來就有的王道進行）**
   每株放開時拿到和弦裡的一個聲部：第一株根音、第二株五度、第三株三度、第四株七度或高八度。和弦走到下一個時，每株各自移到新和弦裡對應的聲部（voice leading），所以幾株一起就是一個會轉的和弦，不是一堆音。
3. **位置和順序決定關係（Ooame JUMP、InkField 的「回應這一筆」）**
   - 畫得靠近的樹繼承鄰居的細分（像 SYNC LOOP），畫得遠的拿不同的細分。
   - 一株播完自己的一輪，把「發言權」交給最近出生的另一株（JUMP）：一問一答，不是全部一起講。
   - 一株枯了，它的聲部空出來，下一株新樹接那個聲部。

這三條加起來，「不同」在細分、音域、素材、效果；「有關」在脈搏、和弦聲部、輪流。

## 4. 結尾

Ooame 沒有結尾，InkField 沒有談。我們已經決定要有：枯。借 InkField 的「餘韻」：枯不是靜音，是 pattern 一格一格熄、最後一個長尾音。熱度退到底，畫面只剩枯枝和底層的風水聲，等下一筆。

## 5. 先做哪個

建議順序（每一步都是一輪可以丟掉的草稿，只做押花樹）：

1. **一株一個節奏物件 + 手勢決定個性**：放開時從這一筆的速度、停頓、種子定下細分、音域、素材、效果、pattern；枝不再直接出聲，而是點亮 pattern 的格子；枯時格子熄。同時做「株數多就每株更稀」的預算。這一步治吵、治單調。
2. **和弦聲部 + 輪流**：每株一個聲部，voice leading；一輪播完交棒。這一步做「有關」。
3. **鄰近繼承、名字**：之後再說。

## 6. 不要照抄的

- Ooame 的視覺（Max 風格的大圖）：我們的畫面是植物，物件之間的連線不畫出來，用聽的。
- InkField 的黃金比例、情緒標籤：作者自己也說是 n=1 的假說。我們只借「速度和停頓帶著狀態」這個方向，不做情緒判斷。
- 兩件作品的程式都不能看，所有實作是我們自己的。
